# ecosystem/exclude.txt
#
# Distributions the ecosystem tools must never pick automatically.
#
# `ecosystem-tickets.py --queue` never offers a listed distribution in the
# ecosystem-dist-queue skill's work order. `ecosystem-sweep.py` skips them in a bulk `--all` /
# `--prefix` / `--status` / `--stale` selection; `--only <name>` still measures
# one explicitly, so a deliberate re-check after a policy changes is not
# blocked by this file.
#
# An entry belongs here only when the distribution was investigated and found
# permanently unfixable without a decision the project has already made and
# does not intend to revisit -- a decision AGENTS.md reserves for the user, or
# a superseding ADR -- never because it "looks hard". This is NOT the same as
# `no_baseline` (rakudo fails it too, so it is already excluded from the KPI on
# its own): every entry here is a distribution rakudo passes and mutsu,
# correctly, cannot -- see each reason below and the ADR/issue it cites.
#
# Format: <Dist::Name> <one-line reason, ideally citing an issue and/or ADR>
# Blank lines and lines whose first non-blank character is `#` are ignored.
# Keep sorted by name.

LibraryMake #12829 -- get-vars dispatches on $*VM.name (moar/jvm) and dies on anything else; mutsu reports 'mutsu' and will not report 'moar' (same principle as ADR-0104; user decision 2026-09-25, see uniprop).
MoarVM::Bytecode #13511 -- its suite parses CORE.c.setting.moarvm found under $*EXECUTABLE.parent(3) (the running compiler's install tree); mutsu is not a MoarVM and ships no .moarvm files, so it can only pass by pointing at a rakudo install.
MoarVM::Profile -- the MoarVM:: namespace is out of scope (user decision 2026-10-23): it reads MoarVM's own profiler output; mutsu is not a MoarVM.
MoarVM::Remote -- the MoarVM:: namespace is out of scope (user decision 2026-10-23): it drives MoarVM's remote debug protocol (its suite spawns `nqp`/moar); mutsu is not a MoarVM.
Rakudo::Version #8945 -- its own BEGIN checks $*RAKU.compiler.name eq 'rakudo'; ADR-0104 already rejected outright ever spoofing .name, so this can only pass by superseding that decision.
uniprop -- dispatches on $*VM.name (moar/jvm/js) and dies on anything else; mutsu reports 'mutsu' and, by the same principle as ADR-0104 (never claim to be another implementation), will not report 'moar' (user decision 2026-09-25). Its moar branch also needs nqp::getuniprop_* / nqp::unipropcode.
