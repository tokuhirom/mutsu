# The opcode dispatch match is split into groups, so a debug build recurses 2.5x deeper

`exec_one_dispatch` was one 7k-line `match`. A debug build gives every local of
every arm its own native stack slot, so each executed opcode held ~140 KB of
stack (release: ~2 KB), and a deeply nested Raku call chain ran out of stack
early: Template::HAML's 100-level partial recursion died with "Too deep
recursion" on a debug binary (96 levels), and recursion through `EVAL` stopped
at ~900 levels.

The arms now live in 17 `exec_ops_group_NN` functions and
`src/vm/vm_exec_route.rs` sends each opcode to its group. The router is
generated by `scripts/gen-exec-route.py`, and `make check-exec-route` fails if
it is stale, if an opcode has no arm, or if two groups claim one. Release
builds inline the groups back into a single function (`inline(always)`), so the
generated code there is unchanged. On a debug build the HAML partial recursion
now reaches 240 levels and `EVAL` recursion 1847.
