# A block's imported env names live in the import region's own layer

What a block's `use`, `need`, `import` or `require` binds through the env (a `sub EXPORT` hook's variables, terms and routines, a lexical type, an enum key, a trait-value `&name`) used to be written into the env and recorded in `imported_env_keys`, with the value it shadowed in `shadowed_env_values`; `restore_import_env_keys` put the env back on exit. `OpCode::ImportScope` now runs its body over an *import region* (`Env::open_import_region`): an import layer, below the block tier the body's own writes land in. Imports bind into the layer (`Interpreter::import_env_insert`); the exit merges the block tier and drops the layer whole, on every exit path, so a shadowed outer binding comes back by itself and nothing is recorded or restored. An `EVAL` whose unit holds an import statement runs over a region too. The scope records only the layer's id; the pseudo-stash, `hide_unit_names_from_frame` and the replay record read the layer. This completes the env half of ADR-8751 stage 1 (ADR-14140); the grant slice was #15665. Per executed region the cost is unchanged within noise (callgrind, debug build: 250.3K Ir per `{ use M }`, 249.8K before).
