# `.AST` of a `:sym` adverb on a declaration name

`token alt:sym<foo> { ... }`, `rule r:sym«a b» { ... }` and `method m:sym<z>() { ... }` rendered the declaration's name as the one identifier string `alt:sym<foo>`. Rakudo builds `Name.from-identifier("alt", colonpairs => (ColonPair::Value.new(key => "sym", value => QuotedString(processors => <words val>, segments => (StrLiteral("foo"),)))))`, with a `<quotewords val>` quote for the `«»` spelling. `name_from_identifier` now splits a flat `stem:sym<text>` / `stem:sym«text»` name the same way (the `name_parts::sym_name` twin of `operator_name`), and the lowering of a Name with that one colonpair spells the flat name again, so `EVAL($ast)` of a method named that way is found by its full name. The sampled `.AST` text corpus shows the `colonpair-vs-fatarrow` and `name-parts-colonpairs` classes this came from (grammar `proto token` alternatives); lowering a `TokenDeclaration` itself is still refused. Test: `t/rakuast/rakuast-sym-adverb-name.t` (raku-identical); the `.DEPARSE` corpus ratchet grows by 10 statements.
