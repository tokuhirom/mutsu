# A nested BEGIN under `no strict` runs at BEGIN time inside an EVAL

`EVAL 'sub f { no strict; BEGIN { $auto = 3; say "ran" } }'` ran nothing (the main program prints `ran` before anything else). The BEGIN lift refused a name nothing in the EVAL'd unit declares, because in an EVAL it may be a lexical of the caller. With `strict` off where the BEGIN sits that name is either the caller's lexical (the prologue runs in the EVAL's frame, so a by-name read and write find it) or an auto-declared package variable, exactly as outside an EVAL, so the lift now accepts it there too. Test: `t/lang/eval-nested-begin-no-strict.t` (string and tree EVAL, caller lexical read and written, two BEGINs sharing one auto-declared name); it and `begin-prologue-no-strict-auto-declared.t` join the `EVAL(.AST)` ratchet.
